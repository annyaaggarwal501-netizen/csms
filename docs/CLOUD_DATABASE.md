# The shared cloud database: Neon (PostgreSQL, free)

The shop's data lives in **one Neon database in the cloud** (region Singapore). Every computer that runs the app
with the same `.env` uses that same database, so:
- the Owner records stock-in → a Staff laptop sees the new stock on its next scan or page refresh
- a bill made at one counter appears on the Owner's dashboard
- a product photo uploaded once shows everywhere

> **Free plan (Neon, 2026):** $0, no card. 1 GB storage per project (our data is about 9 MB),
> 100 compute-hours a month. The database **sleeps after 5 minutes without use**; the first request after that
> takes a second or two while it wakes up. That is normal.

> **Why PostgreSQL instead of MySQL:** there is no free cloud MySQL any more. The tables, columns, data and rules
> are the same as in the SRS; the SQL is written in PostgreSQL syntax. The delivered MySQL files are kept in
> `db/mysql_original/`.

## 1. The Neon project (already done)
- Project **`csms`**, branch **`production`**, database **`neondb`**, role **`neondb_owner`**, region **ap-southeast-1 (Singapore)**.
- All tables, the seed data (50 products, 274 variants, 30 dummy customers, 2 users) and 50 sample product pictures
  are already loaded, together with Flyway's history (V1–V5). The app recognises them on start-up.

## 2. Get the connection details
1. Neon console → project `csms` → green **Connect** button.
2. Branch `production`, database `neondb`, role `neondb_owner`.
3. **Connection pooling: OFF.** The host must **not** contain `-pooler`.
4. **Show password** → copy the connection string. It looks like:
   ```
   postgresql://neondb_owner:PASSWORD@ep-xxxx-xxxx-123456.c-3.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
                └── user ──┘ └password┘ └──────────────────── host ──────────────────────────┘ └ db ─┘
   ```

## 3. Create the `.env` file (on every computer that runs the app)
In the `csms` folder (next to `pom.xml`), copy `.env.example` to **`.env`** and fill in the parts of the string:
```
DB_HOST=ep-xxxx-xxxx-123456.c-3.ap-southeast-1.aws.neon.tech
DB_PORT=5432
DB_NAME=neondb
DB_USER=neondb_owner
DB_PASSWORD=PASSWORD
DB_SSL_MODE=require
```
- One setting per line, **no quotes**, **no spaces** around `=`.
- The file must be named exactly `.env`, not `.env.txt`. In Windows Explorer, turn on *View → File name extensions*.
- `.env` is in `.gitignore`. **Never** put it on GitHub or in a WhatsApp group. Share it privately, only with people who run the app.

## 4. Start the app
```
mvnw.cmd spring-boot:run        (Windows)
./mvnw spring-boot:run          (Mac/Linux)
```
In the console you should see:
```
Database: jdbc:postgresql://ep-xxxx...neon.tech:5432/neondb?sslmode=require...
Successfully validated 5 migrations
Schema "public" is up to date. No migration necessary.
Started CsmsApplication
```
Open http://localhost:8080 and log in.

## 5. Look at the data
- **Neon console → SQL Editor** (branch `production`, database `neondb`). Type a query and click **Run**,
  for example `SELECT * FROM product LIMIT 10;`. `db/week1_queries.sql` has the practice queries.
- **Neon console → Tables** shows each table like a spreadsheet.
- Or use **pgAdmin** / **DBeaver** with the same host, user and password, SSL mode *require*.

## 6. Branches: safe testing without touching the shop's data
Neon → **Branches → Create branch** (from `production`) makes a full copy in seconds. Put the new branch's host in
your own `.env` to test freely; delete the branch when done. The free plan allows 10 branches per project.

## 7. Security: do this before the shop uses the system
- **Reset the database password:** Neon → Connect → *Reset password* (next to Role), or **Roles → neondb_owner →
  Reset password**. Then update `.env` on every computer. Do this whenever the password may have been seen by others.
- **Change the demo app passwords** (`Owner@123`, `Staff@123`, PIN `2580`).
- Every computer with `.env` holds the full database password. Staff could use it to open the database directly,
  so the planned next step is to **host the app online** so the password stays on the server only.

## MySQL vs PostgreSQL: what changed in our SQL

| | MySQL (original) | PostgreSQL (now) |
|---|---|---|
| Auto-numbering ids | `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` |
| Fixed lists (role, status…) | `ENUM('A','B')` | `VARCHAR` + `CHECK (x IN ('A','B'))` |
| Date and time | `DATETIME` | `TIMESTAMP` |
| Pattern check (HSN, mobile) | `REGEXP` | `~` |
| Case-insensitive search | `LIKE` | `ILIKE` |
| Join texts | `GROUP_CONCAT(x SEPARATOR ', ')` | `STRING_AGG(x, ', ')` |
| Insert or update | `ON DUPLICATE KEY UPDATE` | `ON CONFLICT (...) DO UPDATE` |
| Time maths | `INTERVAL 24 HOUR` | `INTERVAL '24 hours'` |
| Today | `CURDATE()` | `CURRENT_DATE` |
| Count matching rows | `SUM(a <= b)` | `COUNT(*) FILTER (WHERE a <= b)` |

Everything else (`SELECT`, `JOIN`, `GROUP BY`, `SELECT ... FOR UPDATE`, transactions) is the same.

## Problems and fixes

| Message | Cause | Fix |
|---|---|---|
| `Connection refused` / `connect timed out` | Wrong host or no internet | Check `DB_HOST` (no `-pooler`), check the internet |
| `password authentication failed` | Wrong password, or it was reset | Copy it again from Neon → Connect → Show password |
| `SSL ... required` / `no encryption` | SSL not on | `DB_SSL_MODE=require` |
| App still connects to `localhost` | `.env` in the wrong folder or named `.env.txt` | Put `.env` next to `pom.xml` |
| `Validate failed: Migration checksum mismatch` | Someone edited V1–V5 | Never edit old migration files; add `V6__...sql` |
| First page load takes a few seconds | Neon was asleep (5 min without use) | Normal on the free plan |
